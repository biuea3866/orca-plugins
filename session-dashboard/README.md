# Orca 세션 대시보드 패널

모든 프로젝트의 세션 상태, 진행률, 작업 요약, 대기 사유를 Orca 우측 패널에서 표시합니다.

**전체**는 현재 열린 에이전트 터미널과 실행 중인 독립 라우터 호출을 집계합니다. 종료된 라우터 기록과 터미널이 없는 에이전트 기록은 제외하며, 같은 터미널의 여러 라우터 기록을 별도 세션으로 중복 표시하지 않습니다. 기존 세션에 정확히 연결된 라우터 모델 이력은 유지합니다.

세션 카드에는 현재 실행 중이거나 최근 사용한 모델·effort를 표시하고, 상세의 **모델 · 추론 강도**에는 질문별 기록을 표시합니다. Codex는 대화의 `turn_context`, Claude는 assistant 메시지를 읽습니다. 기록에 없는 effort는 `확인 불가`로 표시합니다. 같은 프로젝트의 여러 대화는 질문·답변 일치 여부로 구분합니다.

질문마다 자동으로 모델을 선택하려면 [LLM Router](../llm_router/README.md)를 설치한 뒤 새 터미널에서 평소처럼 `claude`·`codex`를 실행합니다. 일반 CLI를 쓰는 플러그인도 같은 라우터를 사용합니다. 대시보드에는 현재 사용 모델·질문별 사용 모델과 effort·선택 이유·학습 정책이 표시됩니다. 실제 공급자 대화 ID로 기존 세션에 연결하고, 연결할 수 없는 플러그인 호출은 별도 기록으로 보여줍니다.

목록은 작업 카드형이며 상세 화면은 질문·요청별 현황을 중심으로 구성합니다. 답변 완료와 요청한 작업의 완료를 구분하고, 진행률·종료 예상·완료 항목·다음 작업·답변 원문을 표시합니다. 카드/상세 화면에서 해당 터미널로 이동할 수 있습니다.

한 세션의 요청을 **주제별로 그룹화**하고 각 주제 안에서는 질문을 오래된 순서부터 표시합니다. 주제 분류는 로컬에서 요청의 핵심어, 후속 질문 표현, 명시적인 주제 전환을 사용하며 추가 모델 호출은 하지 않습니다. 같은 주제로 돌아오는 질문은 기존 그룹에 연결하고 분류 근거를 질문 상세에 표시합니다. 의미를 이해하는 모델 분류가 아니므로 모호한 요청은 별도 주제로 나뉠 수 있습니다. `주제: 로그인 개선`처럼 요청 첫 줄에 주제를 명시하면 같은 제목의 그룹에 연결합니다.

상세의 **주제별 작업 다이어그램**은 세션 → 주제 → 질문 → 작업 과정 → 결과를 연결합니다. 주제 노드를 선택하면 해당 주제의 다이어그램과 질문 기록만 표시하고, 세션 노드로 전체 주제를 다시 볼 수 있습니다. 질문 노드는 상세 기록을 펼쳐 해당 위치로 이동합니다. 주제 선택과 펼친 기록은 실시간 데이터 갱신 후에도 유지합니다.

질문별 **어떻게 작업했나요**에는 에이전트의 작업 설명과 도구 응답 기록을 시간순으로 표시합니다. 도구 응답 수신과 실행 성공·실패를 구분하며, 도구가 응답했다는 사실만으로 작업을 완료 처리하지 않습니다. **완료 기록**은 최종 결과, 확인된 완료 항목, 시각이 기록된 경우 완료 보고 시각, 계획 또는 명시적인 완료 보고라는 판단 근거를 보존합니다. 중간 기록은 질문당 최대 24건까지 표시하고 생략을 명시합니다. 최신 질문은 최대 40건까지 패널에 표시하며 이미 수집해 저장한 주제·완료 기록은 표시 범위에서 벗어나도 `request-history.json`에 유지합니다. 연결된 대화 기록이 없으면 과거 작업 과정을 복원하지 않고 확인 가능한 기록만 표시합니다.

답변 보기와 질문·모델 히스토리의 펼침 상태는 실시간 갱신 후에도 유지됩니다. 모델 · 추론 강도 섹션의 **히스토리 전체 접기** 버튼으로 카드 목록 전체를 숨기고, **히스토리 펼치기**로 다시 표시할 수 있습니다. 목록을 숨긴 상태도 갱신 후 유지됩니다.

Claude 대화 기록의 실제 사용자 요청과 `end_turn` 답변을 연결합니다. 작업 완료는 성공한 계획 항목 또는 에이전트의 명시적인 완료 보고를 근거로 표시하며, 완료 보고를 사용한 경우 그 기준을 화면에 명시합니다. 답변이 끝났다는 사실만으로 작업을 100%로 계산하지 않습니다. 계획이 없으면 단계 추정치 또는 산정 불가를 표시합니다. 종료 예상은 에이전트가 명시한 예상 소요 시간을 사용하며, 근거가 없으면 산정 중으로 표시합니다. 예상 시각이 지나면 재산정 필요로 표시합니다.

Claude 대화 기록과 세션에 일치하는 Codex 실행 기록을 사용합니다. 대화 기록을 찾을 수 없는 세션은 수집 시작 이후 CLI에서 관찰된 요청만 표시하며, 전체 과거 대화를 복원했다고 표시하지 않습니다. 관찰한 요청은 런타임 디렉터리의 `request-history.json`에 저장해 서비스 재시작 후에도 유지합니다. 기록된 요청 목록은 최근 40건까지 표시합니다.

같은 세션과 질문·모델 이력을 패널 데이터에 중복해서 넣지 않습니다. 전송 데이터는 스크립트 경계 이스케이프 후 900KiB 이하로 제한합니다. 한도를 넘으면 오래된 이력·타임라인과 긴 내용을 화면 전송분에서 줄이고 안내를 표시합니다. 최신 요청과 전체 세션 목록을 우선 유지하며 원본 대화와 저장된 요청 기록은 수정하지 않습니다.

요구 사항: macOS, Python 3.10 이상, Orca와 `orca` CLI. 새 컴퓨터에서는 저장소를 복제한 뒤 저장소 루트에서 설치합니다.

```sh
python3 session-dashboard/install.py
```

Orca 설정 → Plugins → Development에서 `~/.orca/session-dashboard/plugin`의 **절대 경로**를 추가하고 `Orca 세션 대시보드`를 활성화합니다. 우측 패널의 `세션 대시보드` 탭을 선택합니다.

macOS 로그인 서비스가 저장소에 포함된 `collector.py`를 사용합니다. 설치 시 수집기와 브리지를 `~/.orca/session-dashboard/`에 복사하므로 별도 수집기를 준비할 필요가 없습니다. 서버나 Chrome 창은 필요하지 않습니다. 생성된 HTML을 Orca의 개발 플러그인 파일 감시기가 다시 읽으므로, 프로젝트를 전환해도 전체 세션을 보여줍니다. 패널 자체는 추가 권한을 요청하지 않습니다.

수집기에 포함된 웹 대시보드의 에이전트 트리·타임라인·계획 표시를 유지하면서, 목록을 작업 카드형으로 바꾸고 상세 화면에 요청별 현황을 추가합니다. 패널 폭에 맞게 간격과 KPI 배치를 조정합니다. 첫 화면은 데이터를 포함해 동기적으로 렌더링합니다. Claude의 계획과 상세 기록은 해당 컴퓨터의 `~/.claude/projects`, 스킬 단계는 `~/.claude/skills`에서 읽습니다.

기본 Orca pluginApi 1은 패널의 네트워크 요청과 사용자 정의 데이터 브리지를 지원하지 않습니다. 기본 모드는 내용 변경 시 HTML 문서를 갱신하므로 상세 화면과 스크롤이 초기화됩니다.

프레임 교체를 없애는 로컬 호스트 수정은 `host-patch/`에 있습니다. Orca 1.4.222 소스에서 데이터만 바뀐 경우 동일한 iframe을 유지하고 `orca-panel-data` 메시지로 새 데이터를 전달합니다. 스크립트 또는 스타일 자체가 변경된 경우에는 기존 재로드 동작을 유지합니다. CSP, scripts-only sandbox, 권한 검사는 유지합니다.

`build_local_orca.py`는 `/Applications/Orca.app`에서 별도 `~/Applications/Orca Dashboard.app`을 생성하고 renderer asset을 수정합니다. 실행 중인 원본을 수정하지 않습니다. 복사 앱은 로컬 서명이며, 공식 업데이트가 이 수정을 포함하지는 않습니다. `host-patch/orca-v1.4.222-panel-data.patch`는 해당 버전 소스에 적용할 수정입니다.

스크롤 유지와 **터미널로 이동**을 사용하려면 Orca 1.4.222 또는 1.4.224, Node.js, macOS의 `codesign`이 필요합니다. 해당 버전이 설치된 새 컴퓨터에서 다음 명령으로 수정 앱을 만든 뒤 기존 Orca를 종료하고 수정 앱을 실행합니다.

```sh
python3 session-dashboard/build_local_orca.py
open "$HOME/Applications/Orca Dashboard.app"
```

수정 앱으로 재시작한 다음:

```sh
python3 session-dashboard/install.py --persistent-frame
```

정식 Orca 앱으로 다시 실행하거나 업데이트하면 로컬 호스트 수정이 적용되지 않아 HTML 갱신마다 패널이 재로드됩니다. 1.4.224에서는 기존 수정 앱을 보존하면서 다음 명령으로 해당 버전용 앱을 만들 수 있습니다.

`--persistent-frame` 수집기는 실행 중인 앱의 화면 유지 지원 여부를 15초마다 다시 확인합니다. 정식 앱으로 전환하면 데이터 수집은 계속하면서 HTML 갱신을 최소 30초 간격으로 제한하고 패널에 현재 모드를 안내합니다. 정식 앱에서는 갱신 시 재로드가 발생하므로 깜빡임을 완전히 없애려면 수정 앱으로 실행해야 합니다. 수정 앱으로 돌아오면 3초 단위 데이터 전달을 자동으로 복구합니다.

```sh
python3 session-dashboard/build_local_orca.py --target "$HOME/Applications/Orca Dashboard 1.4.224.app"
open "$HOME/Applications/Orca Dashboard 1.4.224.app"
```

이 모드는 3초마다 수집한 전체 데이터(마지막 출력 시각과 사용 도구 포함)를 전달하며, 상세 화면의 선택과 스크롤을 유지합니다. 카드와 상세의 DOM 요소를 유지하면서 변경된 텍스트와 값만 반영하며, 작업 중 표시의 반복 점멸 효과는 사용하지 않습니다. 설치 스크립트는 수정 앱이 실행 중인지 확인한 후 활성화합니다. 기본 앱에서는 `--persistent-frame` 활성화를 거부합니다. 수정 앱을 테스트 환경에서 실행하려면 Electron 스킬과 별도의 테스트 프로필을 사용해야 합니다.

진행률은 명시된 스킬 단계/코멘트를 우선하고, Claude의 `TodoWrite` 또는 `TaskCreate`/`TaskUpdate` 계획이 있으면 완료 항목 수로 계산합니다. 계획이 없으면 현재 작업의 확인·분석 → 구현·처리 → 검증 단계를 0/33/67%로 추정하며, `~`와 계산 근거에 `단계 추정`을 명시합니다. 전체 작업량이나 남은 시간을 의미하지 않습니다. 응답 종료 자체는 작업 완료의 근거로 사용하지 않습니다. 새 요청이 들어오면 추정 단계가 초기화됩니다.

카드와 상세 화면의 **터미널로 이동** 버튼은 해당 프로젝트와 터미널 탭·분할 패널로 이동합니다. 연결된 터미널이 없는 세션은 버튼을 비활성화합니다. 이동 중 또는 실패 시 버튼 옆에 상태를 표시합니다. 로컬 호스트의 이동 처리는 이 대시보드 플러그인과 현재 데이터에 포함된 터미널 핸들만 허용하며, 고정된 `terminal.focus` 호출을 사용합니다. 터미널 입력이나 셸 명령을 실행하지 않습니다.

검증:

```sh
python3 -m unittest discover -s session-dashboard -p 'test_*.py'
```

중지:

```sh
launchctl bootout gui/$(id -u)/com.biuea3866.orca-session-dashboard
```

삭제 시 Orca Development 경로를 제거하고 `~/Library/LaunchAgents/com.biuea3866.orca-session-dashboard.plist`와 `~/.orca/session-dashboard`를 삭제합니다.

업데이트는 저장소에서 `git pull --ff-only` 후 설치 명령을 다시 실행합니다. 수정 앱을 사용하는 경우에는 `--persistent-frame` 옵션을 다시 지정합니다.
